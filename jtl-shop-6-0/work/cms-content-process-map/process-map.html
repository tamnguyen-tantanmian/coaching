How a storefront page goes from draft to live

The to-be lifecycle of a CMS content page in one shop: create it, edit its content, publish it, change it once it is live, and take it offline. Each column is one actor; a line into another column is a handover. Orange marks the key moment: the page goes public.

Shop owner and Shop staff have the same rights and can both do every step. The map splits them only to show a typical case: staff build a new page, and the owner later changes or takes down a live one.

Rules the map assumes

  • A new page always starts as a Draft; it is not on the storefront until someone publishes it.
  • Owner and staff can both publish. There is no review or approval step.
  • Editing a live page makes a new Draft version. The live version stays on the storefront, unchanged, until the new version is published.
  • Delete works on drafts only. Deleting the draft of a live page throws away the change; the live version stays.
  • Unpublish takes the page off the storefront (404) but keeps its last version, so it can be published again.
