Theme Settings — Global Setup

Functional documentation for the theme configuration surface: layout, controls, the draft/version/applied model, and every save, apply and reset path a merchant can take.

Status Draft for review Revision v1.0 · 21 Sep 2026 Owner Design — Tam Source Figma board “Theme Settings | Global setup”

1 · Scope

What this document covers

Theme Settings (Global setup) is the theme-level configuration surface inside a shop's admin. Settings defined here — colours, font slots, text styles — apply to every storefront page of the theme. Individual pages are previewed, not configured separately.

In scope

  • Layout anatomy, toolbar, themes rail, preview canvas, configuration panel
  • The Default → Draft → Version → Applied model, including the 5-version ceiling
  • Save as draft, save as version, apply, restore a version, remove a version
  • Reset to default NEW — replaces rollback-after-apply
  • Dialogs, toasts, error, empty and loading states; role-based availability

Deliberately excluded

Out of scope — decided

Unsaved-changes guard. No interception when the merchant navigates away with an unsaved draft. See §16 for the consequence this accepts.

Theme lifecycle. Adding, duplicating, renaming and deleting themes are not specified here. The themes rail is read-and-select only.

Rollback after apply. Replaced by Reset to default at the merchant's direction. Returning to a specific earlier version is still covered by Restore a version (F5).

Control states

Every toolbar control carries the standard set: default, hover, focus-visible, active, disabled. Disabled states must expose their reason as a tooltip — a disabled Apply with no explanation is the single most common support question on editors of this kind.

6 · Preview canvas

What the merchant is looking at

  • Renders the selected page at the selected device, using the editor's current token values — including unsaved changes.
  • Token changes repaint the canvas on a 200 ms debounce. Dragging a size slider updates continuously; committing the value triggers the repaint.
  • The canvas always shows the draft. View store in the shop header always opens the applied version in a new tab. Label the two clearly; merchants conflate them.
  • Selecting a saved version in the picker switches the canvas to that version, read-only, with an inline banner: “Viewing Version 3 — editing is disabled. Restore this version to continue editing.”

Canvas states

StatePresentation
LoadingSkeleton of the page structure, not a spinner, so the merchant can see which page is arriving.
Render errorInline message with Reload preview. Configuration panel stays interactive — a broken preview must not block editing.
Page has no contentPlaceholder page with representative sample content so type and colour remain judgeable.

7 · Configuration panel

Theme name, colours, font slots, text styles

7.1 Panel header & Reset to default NEW

The panel header holds the theme name, a status badge and the reset control.

Theme name
Read-only in this revision. Renaming belongs to the theme lifecycle, which is out of scope.
Status badge
Default when every token matches the theme's shipped values. Customized when one or more differ.
Reset control
Sits immediately right of the theme name. Visible at all times; enabled only while the badge reads Customized.
Decision

Reset-to-default replaces rollback-after-apply. A merchant who dislikes what they published gets back to a known-good state by resetting the theme, not by un-publishing the previous version.

Behaviour

AspectSpecification
TriggerSingle click. No confirmation dialog — the action is immediate, and reversible through Undo.
ScopeThe whole theme: every colour, every font slot, every text style, across every page. Not the currently previewed page only.
ResultThe working draft is replaced with the theme's shipped default token set. Badge flips to Default. Reset control becomes disabled. Canvas repaints.
Does not touchSaved versions 1–5, and the version currently live on the storefront.
Storefront effectNone until Apply. Reset changes the draft only. The live shop is unaffected.
UndoToast “Theme reset to default” with an Undo action, 10 s. Undo restores the exact pre-reset draft.
Per-token resetEach customised control also carries its own small reset affordance, resetting that token alone. Same rules, no toast.
Open — needs a call

Reset returns the theme to default, not to what was live before the last apply. A merchant who applied a good version, then edited and applied again, cannot get the good version back with Reset — they must use Restore (F5) on that version. Confirm this is the intended trade-off, and consider labelling Restore more prominently in the version picker to compensate.

7.2 Colours

Section with a collapse toggle. Tokens, in order: Primary, Secondary, Background, Text, then an Others group for additional named colours.

  • Each row: swatch button, hex input, customised marker, per-token reset.
  • Hex input accepts 3-, 6- and 8-digit values; invalid input reverts on blur with an inline message.
  • The swatch button opens the colour picker; the picker is a shared design-system component, not specified here.
  • Contrast check: Text-on-Background and Text-on-Primary are evaluated live. Below 4.5:1 the pair shows a warning marker with the measured ratio. Warning only — it does not block saving.
Open — architecture

There is no light/dark axis in the data model. Store customisation is a single flat override map, so a merchant's brand colour applies to both schemes unchanged. If light/dark ships as a preset pair, this panel needs a scheme switch and the overrides need a second dimension. Owner: whoever owns ARC-17.

8 · Versioning model

Default, draft, versions, applied

Rules

  1. On first setup, the theme's default configuration counts as Version 1. The editor is never in a zero-version state.
  2. There is one draft per theme. Saving as draft overwrites it; there is no draft history.
  3. A maximum of 5 saved versions per theme. Saving a sixth requires deleting the oldest (F3).
  4. Only the latest version can be applied. Older versions must be restored into the draft first, which promotes them to the newest state.
  5. Applying never deletes a version. The applied version keeps its number and gains an Applied marker in the picker.

Version metadata

Each saved version stores: number, author (account id and display name), saved-at timestamp, and an optional 80-character note the merchant can type in the save dialog. Author and timestamp are not cosmetic — configuration changes must be auditable per §8.17 of the Pflichtenheft, and this list is the only audit surface currently designed anywhere in the merchant flow.

9 · Flows

Eight paths, each with its failure case

F1 · Save as draft

TriggerPrimary action of the split button, or ⌘/Ctrl + S.
PreconditionAt least one token differs from the last saved draft.
SystemPersists the working state to the theme's single draft slot, overwriting the previous draft without a confirmation. Button enters a loading state.
SuccessToast T1. Toolbar save button returns to disabled (nothing left to save). Timestamp in the shop header updates.
FailureToast T6 with Retry. Editor state is preserved; nothing is lost.
EdgeSaving a draft identical to the applied version still writes a draft. The badge does not change.

F2 · Save as version

TriggerSplit-button menu → Save as version.
PreconditionFewer than 5 saved versions. At 5, F3 runs instead.
SystemPromotes the current state to the next version number. Optional note field in the dialog. The draft is cleared — its content now lives in the new version.
SuccessVersion picker switches to the new version and the header shows Saved as Version n. Toast T2.
FailureToast T6. The draft is not cleared.

F3 · Save as version at the 5-version limit

TriggerSave as version while 5 versions exist.
SystemDialog D1 before anything is written. Naming the version to be deleted in the body text is mandatory — “the oldest” is not specific enough to act on.
ConfirmDeletes the oldest version, then proceeds exactly as F2. Toast T3, which names both the created and the deleted version.
CancelNothing is written, nothing is deleted. The merchant returns to the editor with the draft intact.
EdgeIf the oldest version is the one currently applied, block the deletion: keep the dialog open and offer the next-oldest instead. A live storefront must never lose its source version.

F4 · Apply this theme

TriggerApply this Theme.
PreconditionUser has publish rights. The latest version, or the draft, is selected.
SystemIf the draft holds unsaved changes, it is saved as a new version first, so that whatever goes live is always an identifiable numbered version. Then that version is published to the storefront. confirm
SuccessToast T4: “Theme applied successfully — {theme} Version n is now live on your store,” with Open in editor / View store. The Applied chip moves to this theme in the rail.
FailureToast T7. The previously applied version stays live; nothing partially publishes.
EdgeIf applying would exceed the 5-version limit through the implicit save, run D1 first.

F5 · Restore a version

TriggerRestore on a row in the version picker.
SystemDialog D2 if a draft with unsaved work exists, because restoring overwrites it. Straight through otherwise.
ResultThe version's tokens are loaded into the draft. The version itself is unchanged and stays in the list. The merchant can now edit and apply normally.
SuccessToast T5. Badge recalculates — a restored version may be Customized or Default.

F6 · Remove a version

TriggerSplit-button menu → Remove version, acting on the version selected in the picker.
SystemDialog D3. Destructive confirm, named version, no “don't ask again”.
ResultVersion deleted. Remaining versions keep their original numbers — they are identifiers, not positions. The list may read 1, 2, 4, 5.
BlockedThe applied version cannot be removed. Its menu entry is disabled with the tooltip “Applied version — can't be removed.”

F7 · Reset to default NEW

TriggerReset control in the panel header, enabled only while the badge reads Customized.
SystemImmediate. No dialog. The working draft is replaced with the theme's shipped defaults.
ResultBadge → Default. Reset control → disabled. Canvas repaints. Saved versions and the live storefront are untouched.
SuccessToast T8 with Undo, 10 s. Undo restores the exact pre-reset draft.
FailureToast T6. Draft unchanged.
EdgeReset while a saved version is selected (read-only view) is disabled — the merchant must restore first. Reset acts on drafts only.

F8 · First run

EntryArriving from the setup checklist before the shop's theme step is complete.
PresentationThe default theme is loaded and treated as Version 1. Save and Apply are disabled until the merchant makes a first change, with the tooltip “Make a change to save a version.”
ExitThe first successful Apply marks Customize your theme complete on the checklist and returns the merchant there, or keeps them in the editor — confirm.

13 · Engineering notes

Constraints that change the implementation

Preview cannot be an iframe

Tokens reach the DOM as --t-* CSS variables, and CSS variables do not cross an iframe boundary. The admin canvas must run with iframing disabled, which means the mobile preview is a width-constrained container, not an iframe — unless tokens are re-injected inside it.

Font pointers stay as references

A style's slot pointer must be stored as a var() reference string, e.g. --font-h3: var(--t-font-slot-body), and never resolved to a literal at merge time. Resolving it silently breaks store-level rebranding down the merge chain.

Fluid sizing

The token stores the plain base number; clamp() is composed in the stylesheet — min = base × 0.75 for base ≥ 24, interpolated 360→1024px. Storing the clamp string as the token value breaks the merchant's number input. Figma's two modes are the endpoints of that curve, not a separate spec; say so in handoff or it comes back as a bug.

Derived tokens need enforcement

The override type currently permits a partial write to any token, including ones designed as derived. Without an editable-subset type or write validation, “derived” is a convention rather than a rule.

Token cost

This model adds roughly 29 token keys. Each one costs an edit in the token type, the stylesheet, and every theme's base token set. A nested typography object would need a deep merge instead of the current shallow spread — engineering's call, worth making before the keys land.

14 · Acceptance criteria

Per area, testable

Reset to default

  • The reset control is enabled only while the theme's status badge reads Customized.
  • Clicking it resets every colour, slot and text style across all pages, with no confirmation dialog.
  • The status badge flips to Default and the control becomes disabled.
  • Saved versions and the live storefront are unchanged by a reset.
  • A toast with an Undo action appears for 10 seconds and Undo restores the pre-reset draft exactly.
  • The control is disabled while a saved version is selected in the version picker.

Versioning

  • A theme holds at most 5 saved versions and exactly one draft.
  • Saving a 6th version shows a dialog naming the version that will be deleted.
  • The applied version can never be deleted, by any path.
  • Remaining versions keep their original numbers after a deletion.
  • Every saved version records number, author and timestamp.
  • Selecting a non-latest version renders the canvas read-only with a banner and a Restore route.

Apply

  • Apply is disabled, with a stated reason, when the state is already live or the user lacks publish rights.
  • What goes live is always an identifiable numbered version.
  • A failed apply leaves the previous version live and nothing partially published.
  • The success toast names the theme and version number and offers a route to the live store.

16 · Out of scope

And what each exclusion costs

ExcludedConsequence accepted
Unsaved-changes guard A merchant who edits and navigates away — another page, another theme, another tab, or closing the browser — loses the unsaved work with no warning. The draft dot in the themes rail (§5) is the only mitigation. Worth revisiting if support volume shows it.
Theme lifecycle No add, duplicate, rename or delete. Merchants work only with the themes shipped to the shop, and the theme name in the panel header is read-only.
Rollback after apply Replaced by Reset to default. Returning to a specific earlier state requires Restore on that version (F5), which is one level less discoverable than a dedicated rollback.
AI theme setup Present in the prototype and named as the MVP AI surface in the spec, but not documented here. Needs its own flow before build.
Semantic colour tokens Success, warning, error, border and surface colours stay system-locked. Merchants cannot break their own error states — a deliberate constraint, not an omission.
